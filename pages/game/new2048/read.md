“合成大西瓜”本质上是 **物理版 2048**：水果受重力下落、堆叠，两个同级水果碰到一起就合成下一级，堆到顶部超过死亡线就结束。

核心逻辑可以拆成这几块：

## 1. 水果等级
一般有一串等级，例如：

葡萄 → 樱桃 → 橘子 → 柠檬 → 猕猴桃 → 西红柿 → 桃子 → 菠萝 → 椰子 → 半个西瓜 → 大西瓜

每个等级对应：
- 半径
- 质量/密度
- 贴图
- 分数
- 是否能继续合并

最高级通常是大西瓜，两个大西瓜不再合并，或者合成大西瓜即胜利。

## 2. 玩家操作
顶部有一个“待落水果”，跟随鼠标/手指水平移动。  
松手或点击后，它在当前位置变成一个物理刚体，受重力下落。

落下后，顶部再生成下一个待落水果。  
随机生成一般只出前几级小水果，权重偏向小水果，大水果只能靠合并得到。

## 3. 物理部分
通常用物理引擎实现，比如 Matter.js、Box2D、Chipmunk。

水果是圆形刚体：
- 有重力
- 有摩擦
- 弹性很低
- 会碰撞、堆叠、滚动
- 左右墙和底部是静态刚体

所以它不像 2048 那样在格子里移动，而是在连续空间里物理堆叠。

## 4. 合并逻辑
核心在碰撞检测里：

当两个水果发生碰撞时：
1. 判断是不是两个水果
2. 判断等级是否相同
3. 判断是否已经合并过
4. 判断是否已经是最高级
5. 如果都满足，就删除这两个水果
6. 在它们中间位置生成一个“下一级水果”
7. 加分
8. 新水果下一帧继续和周围同级水果碰撞，可能连锁合并

伪代码大概这样：

```js
onCollision(a, b) {
  if (!a.isFruit || !b.isFruit) return;
  if (a.level !== b.level) return;
  if (a.merged || b.merged) return;
  if (a.level >= MAX_LEVEL) return;

  a.merged = true;
  b.merged = true;

  mergeQueue.push([a, b]);
}

afterPhysicsUpdate() {
  for (let [a, b] of mergeQueue) {
    let x = (a.x + b.x) / 2;
    let y = (a.y + b.y) / 2;

    removeFruit(a);
    removeFruit(b);

    createFruit(a.level + 1, x, y);
    score += scoreTable[a.level + 1];
  }
  mergeQueue = [];
}
```

关键点：
- 不要直接在碰撞回调里删除刚体，最好延迟到物理更新后处理。
- 给水果加 `merged` 标记，防止同一帧重复合并。
- 新生成的水果速度通常归零或取平均值，避免飞出去。
- 连锁合并是允许的，比如合成后立刻碰到另一个同级水果，继续合成。

## 5. 结束判定
屏幕上方通常有一条“死亡线”。

如果水果堆得太高：
- 有水果越过死亡线
- 并且停留超过一小段时间，比如 1~2 秒
- 或者新水果已经放不下

就判定游戏结束。

有些版本合成大西瓜后直接胜利，有些版本可以继续玩，冲击更高分。

## 6. 分数逻辑
不同版本不一样，常见有：
- 合成新等级得固定分
- 合成第 n 级得 `n` 分
- 合成第 n 级得 `2^(n-1)` 分
- 连锁合并额外加分

通常小水果合成分少，大水果合成分多。

## 7. 一句话总结
合成大西瓜的游戏逻辑就是：

> 随机生成小水果 → 玩家决定落点 → 物理下落堆叠 → 同级碰撞合并升级 → 大水果堆到顶部死亡线判负。

它和 2048 相同的地方是“同级合并升级”，不同的是它把网格换成了真实物理世界，所以结果更随机、更不可控。
